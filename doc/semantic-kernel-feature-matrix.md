# Semantic-Kernel Feature Matrix

This matrix records the implemented semantic-kernel path, not the capabilities
of the legacy decompiler. It uses three statuses:

- **Certified**: the exact scope named in the row has sealed, artifact-bound
  evidence and rejects mismatches.
- **Residual**: source facts or partial witnesses exist, but the feature lacks a
  closed typed region, render permit, or required execution model.
- **Unsupported**: no positive semantic-kernel construct is admitted; the input
  must refuse or remain residual.

`Certified` is scoped to its row. A certified resource or open-block statement
does not authorize a C function. The currently certified complete functions
are the exact slices named below; each has an independent whole-source closure
and render permit.

## Cross-cutting gates

| Capability | Status | Implemented evidence | Current limitation |
| --- | --- | --- | --- |
| Bounded differential checking | Residual | Independent source/candidate runners cover the admitted open straight-line scalar/plain-memory slice. Specialized runners execute the actual prepared SSA/CFG for the exact branchless guards, private-frame guard, struct-array O0/O2, nested-wrap32 O0, and sum-array O0/O2 functions, including memory events, phis, loop control, signed-32 boundaries, zero/one/many/tail cases, overflow, and deterministic random probes. Compiled bounded probes cover the typed renderers. Loop outcomes explicitly distinguish terminal exit from bound exhaustion. Access width and source/expression fuel are charged before execution, and source return/routing facts are derived from canonical CFG/SSA facts rather than candidate nodes. | `NoMismatchObserved` is bounded falsification only, never proof or render authority. General external execution, post-call state, traps, general phis/stateful loops, general switches, and unknown/word-addressed memory remain outside coverage, and the checker is not a production admission proof. |
| Production decompile route | Certified | For the exact closed subsets named above, including optimized and stack-backed FNV folds, private-frame predicates, O2 branchless guards, the six-block O0 nested-wrap32 guard, struct-array O0/O2, and sum-array O0/O2, `r2engine` receives the required revision-bound source interfaces, reconstructs the r2cert chain, requires the applicable opaque permit, emits semantic C, and reports the exact semantic-kernel region. Exact selection precedes generic renderers and fails closed when a retained fact cannot certify or render. Specialized aggregate-member rendering precedes generic memory, and aggregate pointer authority cannot downgrade an invalid aggregate closure into generic memory C. The direct-call route is reachable from `pdd` only when snapshot/V2 raw-to-lifted call identity is unique and exact. Legacy `r2sym` permission/counters are cleared from those diagnostics. | Every other route residualizes/refuses unless a future closed semantic-kernel composition is added. |
| Immutable radare2 snapshot/provider | Certified | Generic decompiler-provider selection replaces plugin-name checks. Snapshot schema 4 (radare2 ABI 135) owns its copied payload, coherent epochs, completed revision hash, capability-gated function identity, exact register interface, coherent BP/SP stack-resource declarations, and capability-gated exact Local/parameter-Home roles; `pdd` resolves and invokes the selected provider generically. Root CFG, lifted-operation, and aggregate-byte caps reject before context setup or snapshot collection, and lifted-operation accounting is incremental. The public limited collector preflights exact base-type/child counts, every owned base/member/variant name and type string, and assumptions JSON with checked arithmetic before cloning global types; the historical collector remains an unlimited wrapper. Native V2 dynamically requires the limited collector and passes its context/nested/string/JSON aggregate caps, with no unbounded compatibility fallback. | Snapshot capabilities describe captured data, not universal completeness. Variadic/`noreturn`, unresolved or non-full-width base registers, unclassified/overlapping/unsized stack resources, stack-passed arguments, and multi-register returns remain excluded from exact authority. |
| Transactional radare2 mutation | Residual | `r_anal_apply_mutations_atomic` preflights, validates, commits, and allocation-free rolls back call-convention and variable-rename batches, then publishes epochs/events after the complete state is visible. | Other mutation kinds are explicitly rejected by this Stage-1 API; legacy best-effort mutation paths still exist and Phase 10 deletion/migration is incomplete. |
| Generated V2 production FFI | Certified | A cbindgen-checked API table supplies ABI/version/size/capability negotiation, opaque session/response ownership, nested input validation, error borrows, release unwind support, and panic barriers. One native graph carries context, lifted blocks, lift quality, interprocedural scope/plan, analysis depth, timeout, and optional source schema 5 data for decompile or type requests. Owned response metadata exposes diagnostics, outcome, stable phase timings, and explicit FFI-conversion time. Historical V1 request structs/exports/manual C layouts/shim are deleted and guarded by source and linked-library symbol-absence tests. Source schema 5 binds nonzero revision/function identity, explicit BP/SP resources, exact Local/parameter-Home role payloads, exact per-callsite raw/lifted identities, and an optional all-or-none logical type/layout graph; callsite arrays are all-or-none relative to the immutable snapshot. Rust always validates bounded Home-name pointer/length input but treats only parameter index and canonical storage as authority. Checked whole-request budgets cover CFG blocks/ops, context/nested items, individual and aggregate strings/JSON, and allocation arithmetic; C/Rust layout conformance is executable. | Certification covers the generated boundary contract, not ownership transfer of request inputs: the native graph is borrowed for the synchronous call and inner pointer/count nodes remain caller-owned until `execute` returns. |
| Proof-aware benchmark/source-gold closure | Residual | The harness records proof gaps, fake-output classes, residuals, timeouts, source-oracle failures, and owner buckets with strict closure gates. A required fixed-runner job separately probes ABI/plugin/output validity and gates 20-sample in-process command-body p95 plus cold/warm RSS; fast residuals cannot become performance samples. | These gates expose false closure and performance regressions but cannot replace missing semantic witnesses. The fixed-runner deployment label and runner identity remain operational requirements. |
| Phase timing and cancellation | Residual | Every response contains the stable eleven-phase inventory with explicit executed/reused/folded/not-executed/refused status. V2 measures request conversion plus output/diagnostics/response materialization and publishes the total explicitly and in the executed `ffi_conversion` slot. A relative `timeout_us` and session-owned cancellation token are combined into engine execution control; generated cancel/reset callbacks support deterministic pre-cancel and reuse, and refusals return no partial C. SSA and symbolic solver/path/executor worklists poll that control. r2dec now polls its normalization, assignment-consensus structuring, rendering, and semantic-kernel attempts through the same request control; r2engine preserves the exact stopped phase/reason, marks completed inner phases folded, leaves later phases unexecuted, and does not mutate session caches on refusal. | Snapshot/lift remain owned outside the engine timing boundary; obligations/symbolic/certification work can still be folded into broader measured spans. An individual in-flight Z3 check remains non-preemptible. |

Production exact-renderer selection is driven by the prepared artifact's source
facts and opaque permit, independent of legacy decompile-route metadata. That
metadata is consulted only after every exact renderer declines the artifact.

The practical release boundary is therefore narrow: the explicit-interface
single-block scalar return, its exact plain-RAM-memory specialization, and the
exact three-block conditional with two terminal returns can carry the new
`CertifiedC` claim. The two-block direct-void-call/terminal-return subset can
carry the same claim when an authoritative engine snapshot supplies its exact
callsite interface; snapshot schema 4 and V2 source schema 5 now provide that
route when raw-to-lifted identity is unique. The exact switch-return,
carrier-free invariant-loop-return, and canonical unsigned counted-loop-return
functions can also carry that claim when their selector, condition, or bound is
bound to the exact source interface. The eighth closed conditional-funnel
renderer carries the same production permit-backed claim for its exact
register-phi or hidden private-stack carrier. The exact aggregate-member
terminal-return renderer also carries that claim when every memory statement
maps to one member of the same authoritative natural scalar layout. The exact
optimized and stack-backed FNV folds, private-frame predicate, and one-block
x86-64 branchless guards also carry dedicated whole-function permits, as do the
real six-block O0 nested-wrap32 guard, both struct-array lowerings, and both
sum-array lowerings. Everything else above either remains a scoped certified
resource/open fragment or must produce a residual/refusal at the
executable-output boundary.
